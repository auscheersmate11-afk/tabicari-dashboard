# 旅キャリ 共有リストダッシュボード

共有顧客リスト（Googleスプレッドシート）の「顧客リスト」タブを、ページを開いたときに読み込んで集計するダッシュボードです。

- 送信 → 返信 → 面談希望 → 日程確定 → 一次面談 → 二次面談希望 → 二次面談実施 → 成約 の8ステージ
- 期間（全期間/30日/14日/7日）と担当者で絞り込み
- 担当者ランキング（上位10人＋検索・並べ替え・すべて表示）
- 日別の送信数と返信数
- 入力の抜けチェック（担当者・日付・ユーザー名）
- みんなへの貢献ランキング（Discordのコメント・押したスタンプ・もらったスタンプ。`me/community.json` を読む。貢献ポイント＝コメント＋押したスタンプ。これまで／直近7日。上位3人は表彰台＋紙吹雪など。下に目標達成グループ別の合計と1人あたり）

個人のユーザー名はページに表示しません。読み込みには、スプレッドシートの共有設定が「リンクを知っている全員」になっている必要があります。

`?demo=1` を付けるとサンプルの数字で表示します。

## 個別専用ページ（me/）

担当者ひとり分の数字（送信数・返信・面談・成約・メッセージ別・日ごと・チーム平均との比べ）を見るページ。

- URL：`https://auscheersmate11-afk.github.io/tabicari-dashboard/me/?p=<トークン>`
- トークン＝名前から作るハッシュ（スペース・髙/高・かっこの表記ゆれはそろえてから計算）。名簿はページに持たず、顧客リストの担当者名と「LINE案内」タブのお名前をハッシュして一致した人を表示する
- 人が増えたら「LINE案内」にお名前を足して `python3 tools/make_links.py` を実行し、出たURLを「個別専用ページ」列に入れる
- 「みんなへの貢献」：旅キャリDMチーム（Discord）でのコメント（返信も含めた投稿すべて）・押したスタンプ・もらったスタンプ。`me/community.json`（キーはURLと同じトークン・名前は入れない）を ~/cm-discord-archive/tabi_community.py が毎朝作って push する
- 「いまの状況」に、いまの遅れ（今日までの目標との差）・目標まであと何通・1日のペース（送るべき数といまの平均の差）と進み具合のバー。「日ごとの送信」のグラフには目標ペースの線。月500通が目標で、2026年10月だけ特別に10月の分も11月に入れて「11月末までに500通」（今日までの目標は11/1から11/30まで毎日同じ数ずつ積み上げた数。10月中に送った分は先取り扱い）。12月からは毎月500通で前の月の分は足さない（me/index.html の goalPeriod）
- 上の「最新の数字にする」ボタンで、その場でシートを読み直す（Discordの数は毎朝の更新分）
- 「今月の報酬」：今月分の報酬（①DM送信 ②アポ ③成約 ＋調整）の合計・内訳・お支払い予定日、確定待ちの成約、先月分。計算は通知ログスプシの Apps Script「報酬API.gs」（`?pay=<トークン>` で本人分だけ返す・お客様の名前は返さない）で、運営の「支払明細」タブと同じ。`me/index.html` の `PAY_API` にそのウェブアプリURLを入れる。空のあいだ・読めないときは、送信の報酬だけをページで見積もって出す
- `?p=demo` でサンプル表示

## 運営ハブ（hub/）

運営用の入口。`https://auscheersmate11-afk.github.io/tabicari-dashboard/hub/` で、運営ボード（ops/）・DMダッシュボード（claude.ai）・共有ダッシュボード（トップ）をタブで切り替える。

- 運営ボードと共有ダッシュボードはページの中に埋め込んで表示（タブを開いたときに初めて読み込む）
- DMダッシュボードは dm/（下）を埋め込む（claude.ai 版は埋め込みが禁止されているため GitHub に移した）
- `#ops` `#dm` `#share` を付けると最初に開くタブを指定できる。付けなければ前回見たタブ

## DMダッシュボード（dm/）

claude.ai にあった「旅キャリ DMダッシュボード」の GitHub 版。`https://auscheersmate11-afk.github.io/tabicari-dashboard/dm/`

- 旅キャリ 抽出リストの「リスト」タブを、ページを開いたときにブラウザから直接読む（DM文などの長い列は読まない）。数字はページに保存しない
- 上の「最新の数字にする」でその場で読み直す
- 施策メモは `dm/notes.json`（ページからは編集できない。追加・終了・結果の記入は Claude に頼んで notes.json を直す）

## 旅キャリGo（go/）

アポインターがスマホ1つで「配られた人に1通目を送る → 共有顧客リストに記録」まで終わらせるアプリ。`https://auscheersmate11-afk.github.io/tabicari-dashboard/go/#k=<合言葉>`

- 画面はこの `go/index.html` 1枚。データの出し入れは Apps Script「旅キャリ 配布」の `tg_api.gs`（Webアプリ）。毎朝の配布は同じプロジェクトの `td_distribute.gs`（手元の正本は `~/tabi_carry_distribute/`）
- 合言葉は1人ずつ（スクリプトプロパティ `TG_KEYS`）。URLの `#k=` はサーバーに送られない部分なので、GitHub Pages のログにも残らない。名簿や送り先のデータはこのページに持たない
- 今日：配られた送り先のカード →「コピーしてInstagramを開く」（文章をコピーして `ig.me/m/ユーザー名` を開く）→ 貼り付けて送る →「送信済み」で共有顧客リストに1行（日付・担当者・ユーザー名・URL・メッセージA〜D）。「あえて送らない」は理由を選ぶ
- さがす：自分で見つけた相手の**ユーザー名**を入れて重複チェック（2026-11-10〜 ユーザー名の入力欄。先頭の @ は不要・URLを入れても読める）→ まだ誰も送っていなければ、送ったあと「送った！」で共有顧客リストに記入
- 自分：個別専用ページ（me/?p=…・LINE案内タブ D列と同じURL）をそのまま中に出す（2026-11-10〜・iframe・同じサイトなので高さは中身に合わせる）。デザインも数字も個別専用ページと同じ
- 1日40通まで・15通ごとにひと休み。ランク（A/B/C）は出さない
- `?demo=1` で架空のデータの見本（どこにも記録しない）

## Matcha Go!（cm/）

抹茶（Cheers mate）チームの個人ページ「Matcha Go!」。各自の専用スプシ「見込み顧客リスト」の1行目に本人のリンクを入れている。旅キャリGo（go/）と同じ作り・同じ色。`https://auscheersmate11-afk.github.io/tabicari-dashboard/cm/#k=<合言葉>`

- 毎朝の配布・Customer List への記入・回収は今までの仕組みのまま。ページは本人の専用スプシ（◯◯さん専用_抹茶スプレッドシート一覧）の「見込み顧客リスト」で「未送信」の行をカードで出す
- 「送信済み」→ そのシートのステータスを「送信完了」・送った方法を書く／「あえて送らない」→「あえて送らない」・送らない理由（その他はメモにも）
- 送り方（Instagram／メール／フォーム）でいちばん大きいボタンが変わる：Instagram は文章をコピーして `ig.me/m/ユーザー名`、メールは件名・本文入りで mailto、フォームは文章をコピーしてサイト
- 自分：配布台帳の送信完了と Customer List の返信から、今日・今月・累計・返信率・日ごと・文章の番号ごと
- さがす：Instagram のユーザー名で Customer List を重複チェック（読むだけ）
- 受け口は Apps Script（`cm/cm_api.gs` を単独のプロジェクトに貼ってウェブアプリに）。合言葉はスクリプトプロパティ `CM_KEYS`、`cmIssueKeys` で配布先の全員分を作り (元データ) の「個人ページURL」タブに書く。`cm/index.html` の `API` にウェブアプリのURLを入れる
- 端末に覚える値は `cm_` で始める（旅キャリGoと同じサイトなので）
- `?demo=1` で架空のデータの見本（どこにも記録しない）

## セールス逆算（sales/）

`https://auscheersmate11-afk.github.io/tabicari-dashboard/sales/`（運営ハブの「セールス逆算」タブ `hub/#sales`）。今月の成約目標まであと何件か、そのために必要な DM・返信・予約・一次/二次面談、ロードマップ面談（広告経由）の予約・実施の数を、転換率から逆算して表示する。デザインは Cheers mate のサイト（紺・シアン・黄、Manrope＋Noto）に寄せて他のページと見分けがつくようにしている。

- 旅キャリの実績（送信→返信→日程確定→一次面談実施→二次面談実施→成約）は共有顧客リストを開いたときに読む（`tabi.since` 以降に送った分）
- 「ゼロから」と「予定の人も含める」（この先の一次・二次の予定から見込める成約を引く）を切り替えられる
- 表示する月は今日の月に自動で切り替わる。転換率は `tabi.since` からの累計（平均）
- 目標と今月の成約数はページの＋−で変えられ、必要数がその場で変わる（この端末のブラウザに月ごとに保存。初期値は `goals`、旅キャリの今月の成約は 顧客リストの成約数 − `tabi.wonBase[月]`。その月の wonBase がなければ＋−で合わせる）
- `sales/data.json` は手入力：月・目標・この先の面談予定の日付（`upcoming1` 一次 / `upcoming2` 二次、日付が過ぎると自動で外れる）・顧客リストに未記入の二次面談（`extra.n2`）・広告経由のチームの面談結果（`ad.team`）・逆算に使う営業代行の実績（`ad.ref`）。公開リポジトリなので個人名は入れない
- `?demo=1` でサンプル表示

## リスト（list/）

運営だけが見るページ（運営ハブの「リスト」タブ、`hub/#list`）。見た目はチアーズGO! つかいかたブックと同じ紺×金・Inter/Noto Sans JP。共有ページからはリンクしない。

- 上：まだ配っていない A・B・C の件数、あと何日もつか、今日リストに足された数（5分ごとに読み直す）、1日に配っている数（直近7日の平均）
- 「これまでの費用」：Apify の請求書の合計（払った額）、使った分と前払いの残り、時期ごと（9/1〜10/11 有料前・10月 Apify まとめ・11/9〜 返信者のフォロー一覧（無料）・11/26〜 Apify 面談者の近く）の足した件数・1件／A1件／返信1件あたりの費用。時期はリストの L列「追加日」と K列「発見元」（`Apify` を含むか）で分ける
- 「これからの費用」：毎日23:43 $3・日曜21:13 $32・月$250上限から、1か月の費用・増える件数・1件／A1件／返信1件あたり、その追加込みで A／全部がなくなる日
- 費用の数字は `list/index.html` の `INVOICES`（請求書）・`USE`（日別使用額）・`PREPAID`・`PLAN` に手で書く。新しい請求書が来たら `INVOICES` に1行、まとめて取った日は `USE` に1行足して `USE_UNTIL` を進める（それより後の Apify 行は `UNIT_ROW` で推定）。1人1日の上限は `PER_PERSON_MAX`（40）
- 「配る数を増やしたら？」：1日に配る数・A を足す数・もたせたい日数を変えると、あと何日・毎日いくつ足せばいいかを計算（もたせたい日数だけ端末に記憶）
- 下：全体の成約率、ランク別（A・B・C・リスト外）と文章別（A〜D）の返信率と、送信→返信→一次予約→一次面談→二次面談→成約、ランク×文章の返信率（期間：全期間/今月/直近30日/直近7日）
- データ：旅キャリ 抽出リストの「リスト」「リスト（B・C）」「配布台帳」「配布先」と共有顧客リスト「顧客リスト」を、ページを開いたときに直接読む（どちらも「リンクを知っている全員」が見られる設定が必要）。残りの数え方は配布GAS（tdPool_）と同じ。文章の名前は旅キャリGo（tg_api の TG_TPL_NAME）と同じで、`list/index.html` の `TPL_NAME`

## 費用（cost/）

`https://auscheersmate11-afk.github.io/tabicari-dashboard/cost/`（運営ハブの「費用」タブ `hub/#cost`）。リスト作成（Apify）・フォロワー追加（ココナラ）・アポインター報酬の3つを月ごとに合計する。月のプルダウン（または棒グラフのクリック）で数字が切り替わる（カウントアップ・棒が伸びるアニメーションつき）。「これまでの合計」も選べる。見た目はリストページと同じ紺×金・Inter/Noto Sans JP。

- `cost/data.json` は手入力：ココナラの注文（購入日・支払額）、Apifyの請求（ドル、`usdJpy` で円に換算）、月ごとのアポインター報酬の合計（送信・アポ・成約）。公開リポジトリなので個人名・個人別の報酬は入れない
- 月の数え方：ココナラ＝購入日、Apify＝請求日、送信報酬＝送った月、成約報酬＝成約した月
